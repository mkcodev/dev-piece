## Entiende qué hay dentro de tu imagen Docker

Cuando haces `docker build`, cada instrucción del `Dockerfile` crea una capa. `dive` te permite ver exactamente qué archivos añade, modifica o elimina cada capa.

Resultado: sabes por qué tu imagen pesa 1.2 GB y qué hacer para reducirla.

## Uso básico

```bash
# Analizar imagen existente
dive mi-app:latest

# Construir y analizar en un solo paso
dive build -t mi-app .
```

| Tecla | Acción |
|-------|--------|
| `Tab` | Cambiar entre panel Layers / Contents |
| `↑↓` | Navegar |
| `Ctrl+U` | Mostrar solo archivos modificados en esta capa |
| `Ctrl+A` | Mostrar todos los atributos de archivos |
| `/` | Filtrar archivos |
| `Space` | Expandir/colapsar directorios |

## Lo que buscas

Los archivos marcados en **naranja** son los añadidos en esa capa. Los **tachados** son eliminados.

**Señales de imagen mal optimizada:**
- Una capa de `RUN apt-get install` seguida de otra que limpia `apt` cache — si son capas separadas, el espacio no se ahorra
- Archivos de build (`node_modules` de dev, archivos `.git`, cachés) en capas intermedias
- Secretos o credenciales en alguna capa (quedan aunque los borres en capas posteriores)

## Integración en CI

```bash
# Falla si efficiency < 90%
CI=true dive mi-app:latest
```

Con `CI=true`, dive devuelve código de error si la imagen no supera el umbral de eficiencia configurado. Útil para evitar imágenes gordas en producción.

## Mejoras típicas con dive

```dockerfile
# ❌ Dos capas: la cache de apt sigue en la primera
RUN apt-get update
RUN apt-get install -y curl && rm -rf /var/lib/apt/lists/*

# ✅ Una sola capa: limpia en el mismo RUN
RUN apt-get update && \
    apt-get install -y curl && \
    rm -rf /var/lib/apt/lists/*
```
