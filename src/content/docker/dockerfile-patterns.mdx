## Dockerfiles que funcionan en producción

La diferencia entre un Dockerfile básico y uno de producción es la eficiencia (imagen pequeña = desplegues rápidos), seguridad (no correr como root) y cacheo correcto de capas (builds rápidos en CI).

## Multi-stage build para Node.js

```dockerfile
# Dockerfile — Node.js con multi-stage

# ── Stage 1: Instalar dependencias ─────────────────────
FROM node:20-alpine AS deps
WORKDIR /app

# Copiar manifiestos ANTES del código fuente (mejor caché)
COPY package.json package-lock.json ./
RUN npm ci --only=production

# ── Stage 2: Build ─────────────────────────────────────
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# ── Stage 3: Imagen final (solo lo necesario) ──────────
FROM node:20-alpine AS runner
WORKDIR /app

# Seguridad: usuario no-root
RUN addgroup --system nodejs && \
    adduser --system --ingroup nodejs nextjs

# Solo archivos de producción
COPY --from=deps    /app/node_modules ./node_modules
COPY --from=builder /app/dist         ./dist
COPY --from=builder /app/package.json ./

USER nextjs
EXPOSE 3000
CMD ["node", "dist/server.js"]
```

## Multi-stage para Python (FastAPI)

```dockerfile
FROM python:3.12-slim AS builder

WORKDIR /app
RUN pip install --no-cache-dir poetry
COPY pyproject.toml poetry.lock ./
RUN poetry export -f requirements.txt --output requirements.txt --without-hashes

FROM python:3.12-slim

WORKDIR /app

# Sistema: solo lo esencial
RUN apt-get update && apt-get install -y --no-install-recommends \
    libpq5 \
    && rm -rf /var/lib/apt/lists/*

# Dependencias
COPY --from=builder /app/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Usuario no-root
RUN adduser --disabled-password --gecos '' appuser
USER appuser

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Reglas de oro para el cacheo de capas

```dockerfile
# ✅ Lo que cambia poco → primero
COPY package.json package-lock.json ./
RUN npm ci

# ✅ El código fuente → al final (cambia con cada commit)
COPY . .

# ❌ NO hagas esto — invalida el caché en cada build
COPY . .
RUN npm ci  # se reinstala todo siempre
```

## Imagen mínima: distroless

```dockerfile
# La imagen más pequeña posible para Node
FROM gcr.io/distroless/nodejs20-debian12

WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules

CMD ["dist/server.js"]
# Imagen resultante: ~100MB vs ~300MB con node:20-alpine
```

## HEALTHCHECK

```dockerfile
# El orquestador sabe si el contenedor está sano
HEALTHCHECK --interval=30s --timeout=10s --start-period=5s --retries=3 \
  CMD curl -f http://localhost:3000/health || exit 1
```
